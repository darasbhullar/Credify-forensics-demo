How Credify Works

From upload to verdict in four steps

1

You Upload Media

The app accepts JPEG/PNG/WebP images and short video clips. Files are processed locally — there's no external API call. For videos, a handful of frames are sampled across the clip instead of analyzing every frame, making the process fast and efficient.

2

Three Specialized Streams Score the Content

The file is evaluated along three parallel paths: cryptographic credentials checks (Stream A), semantic Vision Transformer patch segmentation (Stream B), and high-frequency Fourier transform noise scans (Stream C).

3

Content Credentials Are Checked

If the file carries valid C2PA Content Credentials signatures (Stream A), the system verifies the trust chain. When provenance matches authoritative generators or cameras, it registers a fast-path verdict immediately.

4

Scores Are Fused Into a Verdict

Classification logits and frequency maps are blended into a unified AI probability. If the final score exceeds 0.5, the media is flagged as FAKE. You also get a detailed spatial heatmap highlighting manipulated zones.

The Three Forensic Streams

Stream A

Provenance SCAN

Performs binary checks for cryptographic JUMBF metadata headers, verifying digital signatures from creators or camera hardware (Leica, Sony, Adobe, OpenAI).

Stream B

Spatial Forensics

Feeds inputs to a SigLIP-2 ViT encoder. A custom convolutional U-Net transposed decoder maps hidden patch states to pixel-level manipulation heatmaps.

Stream C

Frequency Forensics

Extracts grayscale log-magnitude spectra using a 2D Fast Fourier Transform (FFT) and projects frequency grids into a ResNet-50 to catch upsampling artifacts.

Using This in Practice

In a production setting, Credify's output would be one input into a larger decision engine — combined with policy rules, user history, and human review. The system is designed to be an upstream risk signal, not a final verdict.
